# Matching & Recommendation Engine
## Yemen Pharmaceutical Market Intelligence Platform

This document outlines the architecture and logic of the Matching & Recommendation Engine. Moving beyond a simple Offer-to-Request lookup, this engine utilizes multi-dimensional scoring to provide highly relevant connections and alternative suggestions. The engine is updated to handle both official drug list items and free-text entries.

### 1. Core Matching Logic
The matching process evaluates potential pairs (Offers and Requests) across several dimensions, assigning a weighted score to each.

#### 1.1. Dimensions and Weights
| Dimension | Description | Weight (%) | Logic |
|-----------|-------------|------------|-------|
| **Drug Match** | Exact match on brand or generic name, or matching free-text entries. | 40% | If the requested drug is available (either official or free-text), it's the primary match. |
| **Alternative Match** | Match based on active ingredient or therapeutic category. | 20% | If the exact drug is unavailable, alternatives are scored based on dosage and form similarity. |
| **Location Proximity** | Distance between the requesting and offering entities. | 15% | Entities in the same city receive higher scores than those in the same governorate, and so on. |
| **Urgency & Priority** | The critical nature of the request. | 10% | "Critical" requests are weighted more heavily in the queue than "Low" priority requests. |
| **Quantity Alignment** | The ratio of requested vs. offered quantity. | 10% | Perfect alignment scores highest. A slight over/under-supply is penalized slightly. |
| **Market State** | Current demand vs. supply in the region. | 5% | If a region has a severe shortage, the engine prioritizes any incoming offers for that region. |

#### 1.2. Confidence Score
Every match generated by the engine includes a **Confidence Score** (0-100%).
- **Calculation**: The sum of the weighted dimensions, adjusted by data recency and verification status.
- **Purpose**: To inform users how reliable a match is. A match with 95% confidence on an exact drug in the same city is highly actionable. A match with 40% confidence on an alternative in a different governorate requires manual review.

### 2. Recommendation System
Beyond direct matching, the engine provides proactive recommendations to users.

#### 2.1. Alternative Recommendations
When a user creates a Request for a drug that has zero active offers:
1. The system identifies the drug's active ingredients (or searches for similar free-text terms).
2. It searches the Drug Catalog for approved alternatives.
3. It queries active Offers for these alternatives.
4. It recommends the alternative Offers to the user with a "Substitute" tag and a calculated confidence score.

#### 2.2. Predictive Recommendations
Using the **Market Timeline** and historical data:
- If the Demand Index for a specific drug is showing a `Growing` trend in a region, the engine recommends distributors in that region to stock up.
- If the Supply Index shows a `Declining` trend, the engine alerts pharmacies to potential future shortages.

### 3. Search Engine Integration
The matching engine relies on a robust search capability across multiple attributes:
- **Commercial Name** (e.g., "Panadol")
- **Scientific Name** (e.g., "Paracetamol")
- **Active Ingredient**
- **Manufacturer** (e.g., "GSK")
- **Strength** (e.g., "500mg")
- **Form** (e.g., "Tablet")
- **Free Text** (unlisted drug names)
- **Location** (Governorate, City)

The search must support fuzzy matching and Arabic language stemming to handle variations in drug naming conventions, ensuring that both official catalog items and free-text entries are accurately matched.
